# 도서 추가·수정·삭제 수업 실습

태스크 BOOK-MANAGE-20261124 · 요청자 강석현 · 수행 Codex AI

기존 도서관리 앱에 도서 추가와 수정 및 삭제 탭을 연결했다. 수업 화면에 맞춰 `BookInsertPan`과 `BookUpdatePan`으로 이름을 맞췄고, 수정 및 삭제 탭은 위쪽 도서 목록 표와 아래쪽 입력 폼으로 구성했다. 표의 열 순서와 도서번호·재고량·카테고리 라벨을 수업 화면에 맞췄다. Oracle에서 카테고리와 출판사를 읽고, 기존 `BOOK.ISBN` 기본키로 수정하거나 삭제할 책을 찾는다. 도서번호는 고정된다. 수정 저장 또는 삭제 직후 표를 갱신하며, 검색이나 수정 및 삭제 탭으로 이동할 때 해당 목록을 다시 조회한다.

요청에 따라 기존 Oracle에 4권을 등록하고 읽어서 번호, 제목, 저자, 가격, 재고와 연결된 분류·출판사를 대조했다. 동물농장 1004(8,000원), 데미안 1005(8,000원), 이방인 1006(10,000원), 위대한 개츠비 1007(9,000원)이다. 모두 민음사 소설이며 재고는 각 10권의 실습값으로 넣었다. 데이터는 앱과 같은 저장 메서드로 등록했다.

기준 커밋은 `167db3d`다. Java 21 전체 도서 패키지 컴파일을 통과했다. 실제 Oracle 재조회에서 신규 4권이 계속 조회됐다. 수정 화면에서 수업 표의 열 순서, 읽기 전용 표, 행 선택 및 선택 해제, 기본키 고정, 수정 버튼의 변경값 전달과 목록 갱신을 확인했다. 변경값 저장 검사는 모의 저장소를 사용했다. 이후 양쪽 표에 이전 값이 남아 있는 상황을 재현하고 각 탭으로 이동해 해당 칸이 Oracle의 값으로 갱신되는지 확인했다. 양쪽 모두 7권이 조회됐다. 이 탭 검증 과정에서 Oracle 데이터는 그대로 유지했다.

후속 수정으로 검색·수정 표의 마지막 두 열과 입력 폼의 마지막 두 선택칸을 카테고리, 출판사 순서로 정리했다. 실제 Oracle의 `데미안` 행으로 양쪽 표의 제목과 값이 일치하는지 확인했다. 사용자의 최종 요청에 따라 도서번호 칸은 원래의 읽기 전용 색으로 돌렸다. Java 21 컴파일 및 화면 구성 검사를 통과했고 최신 앱을 실행했다.

기본키를 고정하면 화면에서 제목을 바꿔도 어떤 도서를 수정할지 구분할 수 있다. [기존 PR #3](https://github.com/kangseok0427/Study/pull/3)에서 검토한다. 개인 수업 작업으로 회의 공유는 해당 없다.

수업 캡처에 맞춰 `BookRepository.update(Book book)` 안에서 SQL과 `PreparedStatement`를 처리하도록 변경했다. 화면은 카테고리·출판사 ID까지 책 객체에 담아 전달하고, 해당 번호의 행이 없으면 안내문을 표시한다. 전체 컴파일, 실제 Oracle 조회와 버튼을 눌렀을 때 번호·변경값·선택 ID가 새 메서드로 넘어가는 모의 검사를 통과했다.

후속 요청으로 `update` 바로 아래에 `delete(int isbn)`를 추가했다. 도서번호가 일치하는 행 하나를 삭제하면 `true`, 해당 행이 없으면 `false`를 반환한다. Java 21 컴파일을 통과했다. 화면 연결과 실제 Oracle 삭제는 이번 작업 범위에서 제외했다.

이후 **수정 및 삭제** 탭의 우클릭 메뉴에 **도서 삭제**를 연결했다. 확인창에서 승인하면 우클릭한 행의 도서번호를 저장소에 전달하고 표를 갱신한다. Java 21 컴파일을 통과했다. 모의 저장소로 다른 행을 우클릭했을 때 올바른 도서번호가 전달되고, 취소하면 호출이 없으며, 확인하면 표에 결과가 반영되는지 검증했다. 최신 앱을 실행해 실제 Oracle 연결을 확인했다. 실제 도서 삭제는 실행하지 않았다.
